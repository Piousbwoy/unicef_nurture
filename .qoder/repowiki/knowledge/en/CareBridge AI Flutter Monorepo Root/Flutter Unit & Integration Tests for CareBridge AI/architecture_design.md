Tests are organised under `test/` using Flutter's `flutter_test` framework. The top level holds two cross-cutting suites: `rbac_test.dart` pins the exact permission sets for `UserRole.caregiver` and `UserRole.frontlineHealthWorker`, while `reference_data_test.dart` validates the Northern Ghana administrative hierarchy (regions → districts → communities) and language lists. All domain-engine tests live in `test/engines/`, one file per engine (`anc_engine_test.dart`, `barrier_engine_test.dart`, `child_engine_test.dart`, `immunisation_engine_test.dart`, `nutrition_engine_test.dart`, `pnc_engine_test.dart`, `trajectory_engine_test.dart`, `vulnerability_engine_test.dart`, `young_infant_engine_test.dart`). Each engine test imports the corresponding `domain/engines/<engine>.dart` and asserts on static methods like `AncEngine.assess(...)` or `BarrierEngine.detectPatterns(...)`. There is no shared test harness — each file defines its own `main()` with `group`/`test` blocks, constructing minimal input objects (e.g. `PregnancyInput`, `VulnerabilityInput`) directly from `const` constructors to keep assertions deterministic.
