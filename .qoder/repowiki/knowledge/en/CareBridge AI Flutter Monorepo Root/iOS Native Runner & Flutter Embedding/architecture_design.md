This is a standard Flutter iOS project scaffold with three logical layers:
- `Flutter/` contains build-time xcconfig files (`Debug.xcconfig`, `Release.xcconfig`) that include `Generated.xcconfig`, plus ephemeral helper scripts (`flutter_lldb_helper.py`, `flutter_export_environment.sh`) used by Xcode during builds.
- `Runner/` is the Xcode application target. `AppDelegate.swift` extends `FlutterAppDelegate` and implements `FlutterImplicitEngineDelegate.didInitializeImplicitFlutterEngine` to register plugins via `GeneratedPluginRegistrant.register`. `SceneDelegate.swift` extends `FlutterSceneDelegate` to host the Flutter UI through UIKit scenes. `Main.storyboard` instantiates a `FlutterViewController` as the root view controller, and `Info.plist` declares the bundle metadata, scene configuration pointing at `$(PRODUCT_MODULE_NAME).SceneDelegate`, and supported interface orientations.
- `Runner.xcodeproj` / `Runner.xcworkspace` define the Xcode project/workspace and shared scheme.
- `GeneratedPluginRegistrant.h/.m` are auto-generated by Flutter and imported through `Runner-Bridging-Header.h` so Swift can call `register(with:)` on the plugin registry.
Dependency direction is one-way: Swift code depends on Flutter.framework and generated headers; nothing in Flutter depends back on Runner.
